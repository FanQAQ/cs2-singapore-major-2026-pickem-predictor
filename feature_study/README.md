# 0–3 的 BO3 抢图能力检验

同样输掉 BO3，一支队可能大都被 0–2 横扫，也可能反复逼入第三图。这个实验检验它在较量双方的 VRS、近期胜负、对强弱队表现和平均回合净胜之外，是否仍有助预测下次 BO3。对照为网站的「近期表现＋赛区实力」及固定的过关率优先填卡。输入来自已有的赛前事实档。特征、训练及模拟可离线复算。

从 `strategy_v4/series.csv.gz` 使用能唯一关联到实际双方五人、日期、胜负与逐图比分的 BO3。将输方抢得一张图记为 1，被横扫记为 0。在此前已经结束的 BO3 中，以输方当时 VRS 减对方 VRS（每 100 分）拟合条件概率。逻辑回归含截距和分差，两个系数均采用精度 5 的零中心正则。每场计算输方实际抢图减去赛前预期，胜方此场不形成抗横扫观察。过去 90 天的观察须与目标首发至少三人重合，按重合比例和 45 天半衰期加权，分母加八个中性观察。未核实的对局或比分跳过。

在每届原 V4 的赛前 85 天训练样本中，每日先生成两侧队伍的特征和胜率，再加入该日任何赛果。先前训练样本满 35 场后使用与 V4 相同的分差、近期状态、对强弱队表现和回合净胜拟合基础胜率，之前使用初始 VRS 斜率。仅对两队均有可信历史失利样本的已知 BO3，用基础胜率的对数几率为偏置项，估计两队抢图能力差的系数。系数加标准正态先验并限制在 ±2。评估时把该系数应用到当前的赛区实力策略 BO3 上，保留其对手实力、BO 差异和地区修正。两边之一缺历史时保持该对阵的原胜率。这个系数描述与下一场 BO3 胜负的关联；比赛准备、教练及不同时期的地图池都可能影响该关联。

| 五届 Stage 1 的评价 | 赛区实力策略 | 增加历史抢图能力 |
| --- | ---: | ---: |
| BO3 单场胜率 Brier（65 场） | 0.20894 | 0.20799 |
| 已知对手的 0–2 淘汰战 Brier（10 场） | 0.22239 | 0.22105 |
| 实际打到 0–2 的队伍，按赛前可能对手平均后的再败 Brier（20 个参赛席位） | 0.23572 | 0.23618 |
| 最终 0–3 概率 Brier（全部 80 个参赛席位） | 0.10449 | 0.10453 |
| 全败栏 / 所有格 / 过关届数 | 2/10　23/50　3/5 | 2/10　23/50　3/5 |

Brier 越低越好。65 场 BO3 中只有 42 场概率改变。各版本分别使用 24,000 条蒙特卡洛路径生成与评估卡片，采用相同随机数种子 33719。模拟胜负若有改变，后续轮次和对手按各自路径重排。相同随机数下，进入 0–2 的概率逐队相等，因为前两轮均为 BO1。真实 0–2 淘汰战衡量对手已知时的预测，通行证锁定时需要对潜在对手积分，两个指标分母不同。实验未体现可重复的整卡收益，继续作为研究记录。

## 另一个可测量的特征

BO3 中由己方选出的图，能否打出高于该队该图一般水平的胜率？已有禁选模型能估计哪些图可能被选，地图模型能估计每张图的实力；可以进一步检验选择权和实际胜率是否有关。在验证未来模型之前，先检查训练数据。仅采纳禁选档中明确的 Ektarr 比赛编号，并核对地图名、日期、己方当场五人和对手积分日期。每个可确认自选图的战队记一个侧面样本，两支参赛队交手可能产生两个侧面样本。

| 届次 | 有匹配的系列赛 | 参赛队自选图样本 | 有数据的队伍 | 至少 5 次的队伍 |
| --- | ---: | ---: | ---: | ---: |
| 哥本哈根 | 40 | 44 | 11/16 | 5/16 |
| 上海 | 124 | 145 | 16/16 | 13/16 |
| 奥斯汀 | 59 | 72 | 12/16 | 6/16 |
| 布达佩斯 | 87 | 102 | 13/16 | 8/16 |
| 科隆 | 14 | 18 | 10/16 | 1/16 |
| 新加坡 | 96 | 104 | 14/16 | 10/16 |

这项核查只统计覆盖。下一步可以先扣除对手实力和该队该图的一般胜率，在此前已结束赛事拟合自选图的额外胜率，再用下一届验证。队伍变化、地图更新和每队样本不均会限制可用性。

```sh
OPENBLAS_NUM_THREADS=1 python3 feature_study/fit.py --check
node feature_study/score.cjs --check
python3 feature_study/pick_coverage.py --check
```

五届分项成绩见 `report.json`，各届的训练数量、系数、当前阵容样本见 `profiles.json`，自选图的逐队覆盖见 `pick_coverage.json`。输入来源与许可见 `strategy_v4/METHOD.md`、`map_strength/README.md` 和 `map_veto_data/README.md`。
