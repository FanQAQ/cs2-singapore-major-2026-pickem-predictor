# 同一阵容在 Major 的历史表现

检验一个可重复的命题：在已经按双方赛前实力、对手和系列赛赛制估计胜率后，带着同一核心再次参赛的队伍，是否持续高于或低于预期。每场实际胜场减赛前预期胜场。本队以 75% 赛前胜率赢一场，超预期贡献为 0.25；以 25% 赛前胜率赢一场则为 0.75。选手的 Major 参赛届数、夺冠经历在其他模块统计。

## 赛果和阵容归属

CS2 五届的主赛原始来源为 Ektarr 在 Kaggle 的 [Counter Strike Pro Matches v11](https://www.kaggle.com/datasets/ektarr/counter-strike-pro-matches/versions/11)，原件 `cs2_all_tiers_games.csv` 按 CC BY-SA 4.0 发布。该文件 SHA-256 为 `d99aa6a61c5d9018eef587ce28c026df4dd61406fdd46afe7a8d08bdcdcf2972`。本目录的 `all_stages.json` 和 `evidence.json` 对系列赛事实、选手与档期进行了提取、归一和匹配，衍生数据同样按 CC BY-SA 4.0 发布。队伍和选手资料来源及别名原始说明见 `experience/HISTORY.md`。

每场有双方实际出场的五名选手 ID，可获得的逐图名单也须一致。选手转队或俱乐部改名可延续个人身份。已知同名选手依据源 ID 和队属区分，无法区分的名字不能充当赛前三人核心。当前五人与历史实际出场名单直接交集，至少三人才能归入本队。每届统计的比赛数、原俱乐部、五／四／三人重合数、真实与预期胜场均在输出中。只按本届首发匹配，一名选手自己的多次冠军经历不足以把旧队成绩归给新五人。

`all_stages.json` 包含 2024 哥本哈根与上海各 73 场，2025 奥斯汀、布达佩斯和 2026 科隆各 106 场，合计 464 场；每届剔除单独表演赛。含 35 场季后赛。439 场有额外逐图首发，另 25 场由源数据的系列赛出场名单核实。按实际局分与晋级所需胜图数核对赛制；布达佩斯有 8 场官方 BO1 在这份资料的 bestOf 字段误标为 3，均以瑞士轮赛制、1–0 实际局分及单图记录复核。

`evidence.json` 匹配此前发布的赛前概率重建。五届 Stage 1 共 165 场用「近期表现＋赛区实力」的 BO1／BO3 概率，奥斯汀、布达佩斯、科隆 Stage 2／3 共 198 场用该届 Stage 1 之前冻结的近期表现模型，包含科隆 Stage 3 的 33 场 BO3。总计 363 场，其中 340 场可同时验证逐图首发，23 场有系列赛首发。每个阶段先按日期识别真正的 33 场瑞士轮，再按双方实际成员、胜者与赛制对齐历史模型记录。`pSource` 标明采用的预期。2024 后续阶段和五届季后赛没有同口径的赛前 V4 概率，这 101 场不进入主要超预期特征。它们仍可进入以统一 VRS 预期估计的一般线下赛对照。五届都属于赛前资料的历史重建，比分只在对应 Major 完赛后才成为下一届的输入。

## 估计和时间验证

- 对每场记录取该队实际结果减赛前胜率。阵容保留权重为重合比例的平方。每届超预期及信息量在计算阵容权重之前按 `min(1, 4/该届场数)` 缩放，从而深打多阶段的同一届最多贡献四场全阵容比赛的信息。按历史届完赛日至预测截止日计算时间权重，半衰期固定 540 天。
- 用加权残差和除以「2 + 加权 p(1−p) 之和」估计对数几率偏移，2 对应八场五五开比赛的先验信息量。每队估计限制在 ±0.4。至少两届的阵容加权残差与合并偏移同号，才产生候选修正。对阵的偏移为两队偏移之差，因此交换左右队时概率互补。全败／晋级等结果仍由对阵模拟产生。
- 对每个预测日冻结此前已结束的完整 Major。使用过去各届的注册阵容和当时能够看到的核心历史，逐届重新推导候选，在该届所有已知赛前概率的瑞士轮逐场算误差。只用候选确实会改变胜率的比赛评分。从不使用同届前一阶段的赛果更新后续阶段的特征。启用条件预设为至少 30 场、至少两届、严格超过半数的届次 Brier 改善，且总 Brier、对数损失同时下降。
- 新加坡截止前，两届共 88 场能独立检查这个候选；Brier 由 0.21372 变为 0.21716，对数损失由 0.61553 变为 0.62101。实时策略因此保留基础胜率，比较界面可查看候选的数值。0 次历史或 0 个合格样本代表当前档案的覆盖。核心历史重复偏差还可能来自原单场模型长期低估队伍，可结合非 Major 线下赛对照判断。
- `events.json` 包含六届 Stage 1 的赛前阵容和逐届检验。`later.json` 给出六个后续阶段的参赛席位，所有核心历史仍冻结在整届 Major 之前。相同赛事的多个阶段共享验证门槛、统计届数以及每届上限。

## 复核

在项目根目录运行：

```sh
python major_form/prepare.py /path/to/cs2_all_tiers_games.csv --check
python major_form/build.py --check
python -m unittest major_form.test_profile
node major_form/check.cjs
```

从原始发布文件重新提取需提供第一条命令中的 CSV；后面三条只读取项目已有的离线数据。比赛概率、完整赛果及战队标识的映射可由 `region_vrs_eval/diagnostics.json`、`integrated_eval/diagnostics.json`、`region_risk/anchor.json`、`extra_validation/strengths.json` 与对应阶段的赛果复核。
