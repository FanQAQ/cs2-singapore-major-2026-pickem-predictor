# 跨区线下赛与同届状态

每届冻结两个独立候选修正。区域修正估计双方跨区交手时相对赛前积分和全队近况的额外表现。状态修正估计同一套五人能否在同一项线下赛持续超出或低于赛前预期。两项各自先在该届 Major 开始前已结束的其他国际线下赛上验证。网站随后在五届 Major 的完整流程中检验组合效果。

## 来源与筛选

从明确标记 LAN 的归档中提取 BO1 和 BO3。需能用实际已赛地图复原系列结果，每一张已赛图两侧都必须有实际、互不重叠且在该系列内不变的五名选手。沿用原项目核对禁选和系列比分的解析器。排除名字含 Major、RMR 或 MRQ 的赛事。原始归档信息不完整或不符合筛选条件时会失去覆盖；本目录是可复核的比赛子集。

两队当场五人分别匹配至比赛日期之前的上期 Valve 官方地区积分表。使用三张地区榜中的实际五人，保留重合最多、至少三人且唯一的记录。跨地区重叠、并列、积分无法核实或榜单过期 60 天的观察不进入比赛库。目标 Major 的名单也按其自己的赛前快照匹配。队名不参与匹配。证据表保存 2,894 场不重复系列赛的出场名单、地区、积分和结果，比赛 ID 可在 HLTV 赛事页核实。

归档版本和散列分别固定在原项目的 map_veto_data/extract_archive.py 与 extract_singapore_csv.py。早期的 14 个地区榜版本见 history24/build.py 的 REGIONAL，2024 年 8 月之后的月榜取固定 Git 修订 f8c55f250fdef796d708aa32814587932154fa04 的 invitation 下对应日期。ranking_hashes.json 记录所用 42 期、三区共 126 张表的规范化内容散列。schedule.json 从来源的全部 LAN 赛制（含 BO5 决赛）取同年同名赛事最早、最晚观测日，排除跨越训练截止的赛事。仅在赛事的已核实对阵覆盖至少两个赛区时，才将其作为国际 LAN 训练与验证。

## 两项估计

区域修正先分别拟合 BO1、BO3 的 VRS 分差斜率，系数向标准 Elo 斜率收缩。对三个可能的跨区组合，按赛制扣除基于 VRS 的期望，再估计零均值正则化的对数几率偏差，只采用有至少 10 场历史的地区组合。对阶段首发个人组成的球队，取其过去 180 天已完成非 Major LAN，跨俱乐部按三名核心继承成绩。证据量分区内与跨区、完全相同五人与部分相同。半衰期为 90 天。

队伍校正取该五人打跨区赛事相对于自己所有 LAN 的额外表现，扣除已建模的对手差和赛区差；历史稀疏时向零收缩。某队仅有区内或仅有跨区比赛时，球队差异的估计为零。对手的两项队伍修正之差加上赛区修正，最后限制在 ±0.7 的对数几率。两队区域相同、区域未知、历史不足或按届验证未通过时沿用原概率。网站先按 BO1 或 BO3 得到赛制胜率，再应用跨区修正；启用模拟禁选图时，以这个结果估计地图修正后的胜率。

每队 uncertainty.scale 是跨区特异表现的近似后验标准差，单位为对数几率，数据越少越接近 0.5 的先验尺度。对局页的上下范围把地区偏差及两队偏差的标准误按独立近似合成，再展示中心值上下各一个标准误的条件胜率，用于说明证据强弱；其中未计入全部模型误差和比赛随机性。

同届状态以独立基线拟合：先扣除本场 VRS 与赛制，再统计非 Major 国际 LAN 中，同一套五人跨日对阵不同对手时，相邻结果的残差协方差。用期望胜率的导数折算共享实力的方差，小样本向零收缩，对数几率标准差上限 0.5。在留出赛事中，双方各有正、负两种潜在状态，各占一半，起始时校正截距以精确还原原来的单场胜率。仅在该赛事的前一日或更早已有已赛比赛时计分。基于前一天已完成系列赛更新状态分布，检验下一天的概率是否更准。它检验的是一套五人在同一届持续超预期或低于预期的统计证据，原因可能包括阵容、场地或初始实力估计偏差。

## 按时间验证

每届使用在截止日前最近 365 天内开始并已结束的其他国际 LAN。按赛事开始时间排序，最早约三分之二的赛事训练，最后的整届赛事验证。排除横跨分割日期的训练赛事。留出预测使用当时可获取的比赛前 VRS。留出赛中的队伍跨区历史只取该赛事开始前的观察，状态检验同日比赛不互相读取结果。

区域门槛要求先前至少 35 场跨区训练、至少 30 场留出对局且涉及四项赛事。状态门槛要求至少 35 对有效相邻残差和至少 40 场可检验的跨日对局、涉及四项赛事。两项均要求留出 Brier 与 log loss 同时更低，且严格过半数的留出赛事 Brier 改善。验证通过后再用当届全部合格赛前记录估计上线系数；状态尺度另须大于零。门槛是工程实验设定，五届 Major 的真实结果不参与决定某届的修正。

## 复算

`python region_risk/build.py --check` 从证据表重新建立每届系数和留出评分。`node region_risk/check.cjs` 检查全体对阵的双向互补、条件范围、名单与时点，以及回退路径。

重建证据表时下载所列版本的原始结果、Griffin 五份 CSV，以及所列日期的三张地区表。早期表沿用 history24 缓存的日期-地区命名，之后使用原仓库文件名。传给脚本的目录只应包括 ranking_hashes.json 所列的日期。

```sh
python region_risk/prepare.py --archive /path/to/results.json.gz --griffin-dir /path/to/2026-data/archive --tables /path/to/early-standings /path/to/monthly-standings --check
```
